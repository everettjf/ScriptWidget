### 既有基础工作包：可靠存储与默认接线

独立容量实验发现：Mac 的四个 owner、共 8 MiB 记录可由独立进程重读；iOS 模拟器在成功验证 16 个 256 KiB 值、累计 4 MiB 后，下一步返回 `inventoryRequired`。这是该实验的失败点，不能推定为所有设备的固定系统阈值。实验未覆盖签名 App Group 或实际 widget extension。原始结果见 `__Release/capabilities/storage-capacity/`，不能以 Mac 成功替代 iOS 验收。

因此，在增加依赖存储的模板前按以下顺序收口：

1. **文件后端**：新记录按 owner 独立原子保存，身份与事务元数据不再和全部记录挤在同一偏好域。旧 UserDefaults 保留作迁移来源；只在确认确实缺失时返回空记录，损坏或不可读应明确报错。文件后端已接入可注入的原生上下文，目录扫描反例已修复；身份协调器、Runtime、记录管理和动作使用同一可抛错后端。Mac 独立进程容量/并发/中断探针已通过；默认启动已在开发工作树接线，Mac/iOS 模拟器检查记录于执行文档；仍需系统点击、签名容器及设备验收。
2. **统一读写事务**：Runtime、按钮/开关、控制中心、配置、历史与备份恢复使用相同 owner、锁、容量和原子提交语义；覆盖重复点击、并发和失败回滚。
3. **迁移与生命周期**：接齐启动盘点、迁移确认、安装/更新/重命名/删除、库切换和恢复。现已增加按库隔离的原生激活协调器：冻结原始盘点、持久化 owner 计划、恢复中断登记，并通过激活 ID 撤销旧上下文。旧读写迁移屏障已接入 Runtime、原生记录管理和动作，并完成独立进程验证；默认启动工厂及库选择 UI 已在开发工作树接线，尚需设备验收。保留旧值；同名重装不继承旧记录；iCloud 未完成盘点时不猜测归属。
4. **一次切换所有生产入口**：实例隔离的原生编译缓存及语法错误回退已实现，Mac/iOS 模拟器全量检查通过；旧 editor 描述符已冻结安装身份，同名重装后拒绝读写。Web Studio 跨库会话、默认启动/设置和显式资料库刷新已在开发工作树接线，仍需完成系统点击、签名容器与设备性能验证。只读预览、截图样例和 Web Mock 继续与真实记录隔离。
5. **端到端验收**：文件后端复测同等容量、独立进程读写和中断恢复，再做 WidgetKit/App Intents 实际点击、签名容器、iCloud 和设备性能测试。未执行项单独记录，不计为通过。

## 范围与交付原则

iOS、iPadOS、macOS 是当前交付平台。新增 API 明确各平台和系统版本的可用性，不能以 Web Mock 成功代替原生支持。watchOS、visionOS 不在本轮范围。

“尽量全部支持”意味着逐项实现或完成可复核的可行性结论。对于系统禁止或不提供公开接口的效果，提供可用替代方案，明确限制，不返回伪装成真实数据的值。尤其不承诺任意应用音乐控制、系统级实时监控、精确后台刷新或小组件永久动画。

每个阶段独立验收，本次 M1–M5 收尾验收后统一准备版本上传，M3–M5 计入发布范围。基础能力复用现有 Runtime、Package 2.0、Gallery、Data Source Plugin 和动作声明，避免另建一套接口。现有脚本返回值保持兼容；新增权限或契约先设计版本和迁移，再实现。

## M1：统一数据、权限、预览和时间线基础

新能力都经过同一条路径：原生提供真实数据，扩展读取有界缓存，Web 提供可编辑的默认样例，模板负责呈现数据和状态。内部可以统一数据提供层和缓存元信息，但不能为了统一而改变已有公开 API 返回结构。

- [ ] M1-1 编制 API 能力目录：平台、最低系统版本、权限、返回结构、同步/异步、缓存、Mock 和模板；与原生实现及静态编辑器元数据建立一致性检查。
- [ ] M1-2 定义可用、未授权、拒绝、无数据、不可用、离线与过期等状态。应用内发起授权，组件扩展不承担首次弹窗流程。
- [ ] M1-3 为新增权限、最低 Runtime 和平台能力设计包契约。未知声明继续拒绝；需要升级契约时同时给出迁移方案。
- [ ] M1-4 建立受限数据查询、缓存和刷新策略：数量/时间范围上限、过期标识、离线回退、撤权清理。先测现有耗时和内存，再设每类数据预算。
- [ ] M1-5 审计动作的读改写和跨进程一致性，补原子更新/幂等保护，验证重复点击和应用/扩展同时更新记录。
- [ ] M1-6 每个新增数据 API 同步提供 Web 默认 Mock、可编辑返回值及错误场景。Mock 保留在 Studio 项目预览设置，不成为用户真实记录或生产包数据。
- [ ] M1-7 设计有界的多条时间线及刷新策略，验证跨日、时区、夏令时和系统延迟；避免承诺分钟级准确后台执行。

出口：选一个新增只读 API 跑通“授权—真实数据—缓存—原生组件—可编辑 Mock—测试—文档”全链路，作为后续实现样板。

### 当前关键路径：记录隔离与安装身份

| 增量 | 具体工作 | 出口条件 |

记录模板已有真实写入、配置、历史和备份恢复的开发实现。下一步先完成下面的依赖链，再扩展依赖同一存储层的新模板：

1. 验证原生 UUID 身份与旧记录迁移协调器：保留原值、断点恢复、点分名称歧义、重名复用、容量和多进程并发。协调器测试通过只代表该模块通过，不能视为生产运行时已经迁移。
2. 接通原生安装事务：新建、导入、复制、Gallery 安装获得新身份；重命名保留身份；删除后同名新安装不能读取旧记录。处理文件发布与身份登记之间的崩溃恢复，并覆盖共享扩展入口和缓存回退。
3. 接通应用启动盘点与迁移界面：只有原生盘点可以分配旧记录；iCloud 目录不完整时不推定缺失包不存在。歧义记录先预览归属，保留原值，可选择不分配；预览后变化必须重新确认。
4. 一起切换运行时、按钮/开关和原生记录管理器，统一身份、锁和容量预算。只读模板预览使用隔离数据；迁移未完成或身份不可用时显示明确状态，不能当作空记录继续写入。
5. 回归旧包、模板更新、日期边界、断网/驱逐缓存、重启和设备端点击；全部调用方和生命周期接通后，才将 M1 存储隔离标为已验收。

## 每项能力的完成标准

- 原生真数据和动作已接通，平台/版本可用性明确；权限拒绝、撤销、无数据和离线状态可解释。
- 查询、文件和网络使用有上限；组件缓存、刷新与动作并发符合预算，敏感数据和凭据不进入日志或导出。
- Web 有最佳状态的默认样例，可编辑 Mock，且覆盖异常情况；清楚标记模拟，不伪装真实授权。
- API、包契约、静态编辑器补全、AI 上下文、文档、生成 bundle 和模板同步更新，旧包兼容通过。
- 有确定性回归测试；涉及 UI 的原生构建和截图完成，涉及设备能力的真机验收留下型号、系统版本和结果。
- 按仓库要求运行聚焦检查及 `./Scripts/release-readiness.sh`，关联实际成功证据，列出未执行项目。
- 发布说明准确，记录首次包含该能力的构建及回退方式。截图假数据和真实模板记录相互隔离。

覆盖表使用“未开始 / 原型 / 开发 / 待验收 / 已验收 / 已发布 / 平台受限”状态。只有达到上述标准并进入可追踪发布构建，才标为已发布。后续实现按本计划更新清单与证据，而不是按宣传页面推定完成。
