A 表示已有基础可组合，不等于未经测试即可发布；B 表示有基础但还缺数据、配置或系统适配；C 表示需要新增原生能力、服务或独立产品模块。以下是依据代码作出的工程判断。

优先做什么

第一批 · 模板与体验

把已有能力变成好用作品

  • 真实习惯/饮水/心情打卡
  • 照片拼贴与原创主题套装
  • 年份进度、倒计时、时间面板
  • 真实步数/活动能量健康卡
  • 公开 JSON 数据与天气组合卡

优先级高；不先扩大原生权限。每个模板配置参数、离线/失败状态和各尺寸验收。

第二批 · 数据与配置

先补日常实用缺口

  • 日历/提醒事项只读数据
  • 照片库有限权限与轮播
  • 启动动作目录和配置引导
  • 壁纸截图拟透明向导
  • 更完整的健康时间范围查询

中等以上投入。每项先定义版本化 API、权限、缓存和 Mock，再做原生与 Web 一致验证。

后续立项 · 独立系统

按新增用户价值决定

  • 真实音乐控制及账户服务
  • 跨用户互动和共同宠物
  • 远程 Live Activity 推送
  • Apple Watch 原生目标
  • 拖拽图层可视化编辑器

高投入；涉及凭据、账户、服务器或平台目标，不应作为几个新模板直接排期。

对我们宣传图的启发

  1. 首屏先给成果：用自己的原创组件组成真实桌面场景；保留 JSX 定位，但不要让用户先读懂代码才明白用途。
  2. 同一套视觉贯穿：壁纸、组件色彩、字体和图标互相呼应，比堆很多不相关示例更清楚。
  3. 每张只表达一个用户收益：个性化桌面、记录习惯、看真实数据、一次创作适配多尺寸、代码可修改、跨设备分享。
  4. 交互有前后状态：用实际按钮和真实模板拍摄“未完成→今日完成”，示例历史只用于截图，不伪造产品功能。
  5. 编辑器放在成果之后：展示修改 JSX/颜色如何改变同一组件，并把 Web Studio、Mock 和导出作为创作流程的差异点。
  6. 不要借用未接通的数据能力：静态歌曲卡片不当成音乐控制器，参数列表不当成真实日历；只承诺已经验证的刷新与动画效果。

  • Apple：保持 Widget 最新 — 更新受系统预算、上下文与策略管理；不能从截图推导出无限后台刷新。
