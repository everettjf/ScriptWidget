## B：创作体验候选，发布后另选批次

- [ ] **N01 三端创作体验**：基于实际使用问题整理布局/主题/素材/壁纸的端到端体验，改善诊断、无障碍和文件资源流程；先列具体问题及验收范围，避免泛化重写。
- [ ] **N02 公开动画兼容方案**：对旧时钟/摆动/iOS GIF 桥接做公开 API 原型、兼容和静态回退验证，再决定替换。当前有界 GIF 解码不等于已移除私有动画桥接。
- [ ] **N03 可视化 JSX 子集扩展**：明确需求后逐项扩大；动态表达式继续可用 Code 编辑；源码往返和撤销不得破坏不支持结构。

## C：音乐与服务候选，满足条件后再启动

- [ ] **S01 Spotify 配置与真实验收**：取得 Client ID、注册回调、核验实际分发资格；验证系统登录/刷新/撤权和签名 app/widget。用户目前暂无配置，保持未配置提示，不重复要求现在提供。
- [ ] **S02 Spotify 控制授权**（依赖 S01）：控制 scope 明确申请/重新登录、逐组件授权。读取权限不能隐式升级成控制权限。
- [ ] **S03 Spotify 控制实现**（依赖 S01/S02）：有界 HTTP writer、公开控制 API、主动动作上下文、取消/预算及派发前后身份复核，操作 UI 和模板形成闭环。复用内部记录，覆盖重复请求、未知结果和恢复；不自动用新 requestID 重试，不承诺服务端 exactly-once。
- [ ] **S04 Web 控制 mock**（随 S03 同批交付）：正常状态变化、回执、重复操作、撤权、错误及未知结果，仅修改预览数据；包含默认正常样例、可编辑配置、文档和回归。
- [ ] **S05 Spotify 后台刷新**（依赖 S01）：在已有前台刷新之外，设计跨进程协调、过期、竞争和扩展预算并验证。
- [ ] **S06 Apple Music 扩展原型**：核验公开播放控制、队列/订阅和平台限制，真实设备证明后再定 API/模板/Web mock 范围；当前只读快照保持现状。

S02–S04 是一个完整候选批次，不以只有按钮或只有 mock 作为交付。优先系统框架与官方 HTTP，减少第三方 SDK。

## 更新规则

按 ID 更新任务状态并链接实际验证结果。功能完成、自动化通过、真机验收、已部署、已上传分别记录。阶段 A 不等待 B/C/D；未来批次须用户重新选定范围后开始，不因 TODO 存在而自动继续开发。
