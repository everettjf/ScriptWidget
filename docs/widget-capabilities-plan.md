## 阶段 A：当前版本验收与发布

**当前唯一优先级。范围冻结，只修复已有能力的验收问题，不增加新功能。**

按顺序推进 [TODO 的 R01–R07](widget-capabilities-todo.md)：

1. 固定发布功能表：原生/Web 支持、配置前提、不可用状态和宣传口径逐项对应。Spotify 当前按未配置不可用处理；Music 当前是 iOS 只读能力。
2. 验收真实个人数据及服务边界：系统授权/撤权、有限照片选择、提醒事项动作、GitHub、Keychain、组件 owner 和共享容器。
3. 验收系统实际表现：WidgetKit、点击、锁屏、Live Activity/Control（适用项）、Clear/Tinted/Always On、扩展内存和旧动画路径。旧私有桥接要有明确发布处置结论；发现阻塞时修复或明确调整发布范围，不默认通过。
4. 完成 iPad/iCloud/构建矩阵和最终回归，整理版本说明、截图及版本号。
5. 在发布验收通过后部署 Web、归档/上传原生构建并核对线上版本。App Store Connect 如需重新登录由用户操作，App Review 由用户提交。

出口：适用发布清单都有证据或明确范围处置；Web 部署和原生上传分别可追踪；本轮功能说明准确。不能用自动化测试全绿替代真机、签名或商店验收，也不等待后续播放控制、完整动态 JSX 编辑或 Watch。

最近实现版本的完整本地 gate 已通过（Mac 706 / iPhone Simulator 716，0 失败）；这是开发基线，不表示上述发布验收已完成。具体跳过项和路径见 [执行记录](widget-capabilities-execution.md)。

## 阶段 B：下一版本候选——完善创作体验

**发布阶段 A 后，再由用户选择是否启动。** 优先处理实际使用中暴露的问题，不提前铺开更多系统 API。

- `N01`：复核三端创作完整流程，按实际问题改善诊断、操作提示、无障碍和文件/资源工作流；已有子集先做到顺畅可靠。
- `N02`：按可复核原型处理旧时钟/摆动/GIF 动画的公开 API 替代，验证静态回退和兼容。阶段 A 的风险评估不能替代这项实现。
- `N03`：仅在有明确需求时扩大可视化 JSX 支持子集。动态表达式保留源码编辑，无法可靠往返的代码不得自动改写。

出口：每批有独立演示、跨端回归和更新说明；不承诺一次覆盖任意 JavaScript。B/C 是候选方向，不是必须全部完成才能发版的连续大工程。

## 阶段 C：下一版本候选——真实音乐与服务控制

**按服务独立推进；外部配置和官方能力先验证，避免先做完界面再发现不可用。**

| 顺序 | 工作 | 前提与出口 |
| --- | --- | --- |
| C1 / `S01` | Spotify 真实接入验收 | 注册 Client ID、回调及分发资格可用；真实登录、刷新、撤权及签名 app/widget 验收。当前用户暂无配置，保持待条件具备 |
| C2 / `S02–S04` | Spotify 控制完整闭环 | C1 可用后，控制授权 → 有界原生 writer/公开 API → 操作界面/模板 → Web 状态化 mock，合为可验收批次 |
| C3 / `S05` | Spotify 后台刷新 | 设计跨进程协调、过期、竞争和扩展预算；原有前台刷新不算后台完成 |
| C4 / `S06` | Apple Music 扩展评估 | 先验证公开控制、队列、订阅及平台限制；原型证明可用后再定义实现范围，不从 iOS 只读成功推导全面支持 |

控制接口必须由用户主动触发，权限按组件明确授予。复用内部操作记录，但它只有本地重放保护，不能保证第三方服务 exactly-once；未知结果不能自动换 requestID 重试。优先系统框架和官方 HTTP，减少第三方 SDK。

每个公开增量同时交付原生实现、适用的 Web mock、默认正常样例和异常场景、补全/文档/模板及测试。Web 不取得原生凭据，也不伪装成真实服务授权。

## 阶段 D：长期探索，不排入近期版本

- `L01`：远端更新、APNs 和运行维护方案；保留本地 Live Activity 路径。
- `L02`：好友/情侣共享、配对/解除、隐私、数据删除与同步恢复。
- `L03`：Watch 技术原型、平台目标、同步及实体手表验证。
- `L04`：系统监控和其他平台极限能力，逐项核验公开接口；无法支持的给出明确限制。

这些方向需要单独产品决策和原型，不作为近期承诺。visionOS 不在本规划内。
