# Public data cards

GitHub Repo Stats is a complete public JSON card example: saved public repository and accent, native configuration/restore, one declared API host, validated payloads, bounded persistent cache and eight display families. It uses `$http.getResponse`; existing generic Data Source Plugins remain the route for declarative HTTPS mappings. This increment does not establish authenticated service support.

The GitHub card accepts the legacy `owner/repository` parameter or JSON overrides. It rejects URLs, traversal, credentials and unknown settings. Only valid public payloads for the expected full repository name are accepted; missing counts never become fabricated zeros. `open_issues_count` is labelled “Issues + PRs” because GitHub treats pull requests as issues ([GitHub Issues API](https://docs.github.com/en/rest/issues/issues)).

Cache policy: at most four repositories and fourteen actual daily star checks per repository (UTC buckets), at least one hour between successful refreshes, conditional Last-Modified requests when present, retry backoff, seven-day maximum displayed cache age. Cache commits use compare-and-set and preserve other repository entries. A 404 clears old counts/history; network and rate failures retain labelled cached counts. Empty cache cannot pretend to be a successful zero. Future projections only read the cache. Configuration backups exclude transient API history.

Anonymous requests share an IP quota. Conditional requests are not universally quota-free. GitHub's [best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api) govern backoff, and [rate-limit guidance](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) explains shared anonymous limits. The template pins API 2022-11-28, still supported through March 10, 2028 according to the [version table](https://docs.github.com/en/rest/about-the-rest-api/api-versions) checked on 2026-10-21. An API version update requires separate verification.

The default Web Mock and bundled native preview use synthetic counts and are explicitly documented as examples. The trend appears only after two recorded days; it does not invent earlier GitHub history. Native acceptance tests inject a local URLProtocol into an ephemeral session, checking installation, the real HTTP bridge, absent Authorization, cache persistence and reopening. They do not prove live service availability or signed-device WidgetKit behavior.
