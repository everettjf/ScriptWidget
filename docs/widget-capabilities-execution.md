## 下一条真实数据链路

按 M1 → M3 的依赖继续实现日历纵向链路：先设计显式包权限和有界查询/缓存，再接 EventKit、应用内授权、组件只读缓存、Web Mock、编辑器/AI 参考和真实日程模板。现有 `.health` / `.location` 包声明与旧 API 行为不能被目录描述误认为已经统一了运行时权限控制。新增能力需要实际拒绝未声明权限和异常清单，不能仅添加 enum 或界面字段。

Apple 官方接口核验：日历读取在 iOS 17+ 使用完整访问授权，应用需要对应说明键；macOS 沙盒日历访问需要相应 entitlement。健康读取授权不暴露每种读取权限的拒绝情况。音乐授权和服务资格需按服务分别验证。凭据托管需独立于已有 AI OAuth 账户，不能把 AI token 引用提供给组件脚本。

## 最低 Runtime、预执行校验及 Health 隐私语义

- `minimumRuntimeVersion` 是可选的 native 公共 API 下限（例如 1.3），与 Package 2.0 的 `runtimeVersion: 1.0` ABI 分开。版本必须是规范的 major.minor；未来 minor、不兼容 major 和错误类型均拒绝，旧项目省略字段仍可运行。
- 原生 Widget、Dynamic Island、动作三条执行路径在编译/缓存命中/用户代码之前校验清单；Web 在独立编译 Worker 中同样校验。文件内清单权威优先，宿主对象不能覆盖它；files-only 任务也按清单选择入口。
- 已添加原生回归，证明不兼容包不能执行存储副作用；Web 回归覆盖编译器未被调用、无效/未来格式、冲突的宿主清单和嵌套入口。
- 原生公共版本由 Common 层常量统一，编辑器元数据改为对应的 1.3 公共 API 版本，目录为每种数据方法标记最低版本。该轮 preview engine 为 0.5.0（后续原子存储批次升至 0.6.0）。
- Health 设置不再为推断授权而执行样本查询，不再显示“已授权/部分授权/拒绝读取”的错误结论；改为需要权限复核、已完成复核或不可用，并在返回前台后刷新。
- 新增 `$health.authorizationStatus()`，可用设备返回 `notDisclosed`，不可用平台返回 `unavailable`。授权复核使用同一份原生类型集合。AI 提示、Web 的 No shared data/服务不可用场景和文档同步更新；修正了 AI 提示中不存在的 `$storage.set/get` 方法。
