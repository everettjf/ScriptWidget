# Launchers and declared system actions

Quick Launcher now saves one to six web/app/Shortcut links through the same bound configuration store as other templates. Its `launcher` Record Backup 1 kind owns only `recordTemplate.config.v1`, with `title`, `accent` and ordered `items`. Item fields are closed and bounded; names, icon choices, schemes, credentials, percent escapes, ports and duplicate IDs are checked natively and in the browser helper. Its configuration-only allowance is 32 KiB; existing kinds keep their 4 KiB configuration limit. The backup includes link destinations and optional shortcut text, never network access or new runtime permissions.

Named Shortcuts use Apple's documented `shortcuts://run-shortcut` URL with encoded `name` and optional `input=text&text=...` ([iPhone/iPad](https://support.apple.com/guide/shortcuts/apd624386f42/ios), [Mac](https://support.apple.com/guide/shortcuts-mac/apd624386f42/mac)). No clipboard access or shortcut discovery is implied. The native test button uses [OpenURLAction completion](https://developer.apple.com/documentation/swiftui/openurlaction/callasfunction(_:completion:)); this reports system acceptance, not completion of a target-app operation. The native forwarding path handles hostless URLs such as mailto/tel and shows a generic unavailable-handler message without printing a complete URL.

The compact launcher uses its first item, medium its first three, large families up to six. The root `linkurl` supplies a primary fallback and compatible link tiles supply individual targets. See [WidgetKit linking guidance](https://developer.apple.com/documentation/widgetkit/linking-to-specific-app-scenes-from-your-widget-or-live-activity). Real OS/size routing remains a device acceptance item; render-tree parity does not prove that a link opens an app.

Hydration Goal, Mood Check-in, Packing Checklist, Habit Streak Tracker and Habit Heatmap now declare their named handlers in the existing Package 2.0 `actions` and `controls` contracts. Widget buttons use `actionID` and resolve through the same identity-bound catalog as Shortcuts and Control Widgets. Record formats, actual handlers, undo/reset semantics and owner boundaries are unchanged. Checklist slot actions require that the corresponding item is configured; unset slots fail clearly instead of inventing records.

Settings on iOS and the Widget Actions tab on Mac display that same native catalog. Listing actions does not run package JavaScript. Entity subtitles and the directory use the actual installation name, so copies with the same public manifest ID remain distinguishable. The directory refreshes current installed metadata and lists compatible controls; it does not grant new tools, permissions or cross-package function execution.

Control Switch is a separate, honest local-flag example. Its declared toggle uses `switch.enabled`, and explicit true/false values use the existing SetValueIntent path. A generic Shortcut call toggles; explicit on/off actions set a value. It is not system Focus or HomeKit. The flag persists in the package's owned storage and is not inherited by a same-name reinstall. It is not part of the daily-record backup kinds, and script export does not contain the flag.

Both declared and legacy native action completion now request a widget refresh plus, on compatible iOS, a reload for ScriptWidget.Button/ScriptWidget.Toggle controls. Apple documents [requesting control reloads](https://developer.apple.com/documentation/widgetkit/updating-controls-locally-and-remotely) when shared app state changes. These are requests, not an immediate refresh guarantee. Signed-device Control Center/Shortcuts discovery, actual taps and lock-screen behavior remain separate from deterministic executor tests.

Existing installed user copies are not automatically rewritten. To adopt a newer record template while retaining compatible records, explicitly export its record backup, install the current template as a separate copy, and review/restore that backup into the new matching kind. This never grants the replacement installation the old owner identity.
